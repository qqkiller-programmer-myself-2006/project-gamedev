# Client / Story mode UI / tools review — 2026-09-29

Scope: committed code `52113a0...HEAD` (HEAD `41acda7`). Files: `src/client/**`, `src/app/**`, `tools/ui_preview.gd`,
`tools/story_preview.gd`, `tools/slice_character_sheet.py`, `assets/characters/manifest.json`, and the export presets where
they affect the client. This is a read-only review. Godot was not run. Every finding was traced in `git show HEAD:<path>`,
and line numbers refer to HEAD. Uncommitted #60 work in the working tree was not reviewed.

What checked out:
- **Sprite manifest:** all 168 frame paths in `assets/characters/manifest.json` exist under `assets/characters/<class>/`.
- **Acting character in Story battles:** `battle_view.gd:185` uses the current actor as "me". `_send` (`:848`) does not add a
  `slot`, so the server routes the action to the actor (`room.gd:137-155`). Camp commands send `_acting_slot()` = the inspected
  character in Story mode (`camp_view.gd:493`).
- **Known fixes are still in place:** the Playtest port fallback and never-quit (`client_app.gd:187-195`), the ui_preview
  Multiplayer path (`ui_preview.gd:80-83`) and sprite scale by body height (`battle_token.gd:247`).
- **Esc inside modals:** `ConfirmDialog` swallows every key and keeps Tab inside the dialog. `DialoguePanel` owns Enter and
  Esc (see C15 for the keys it lets through).
- **Web build:** nothing in the client runs Python, opens an embedded server (`can_playtest` excludes web) or uses absolute
  file paths. `JavaScriptBridge` is only used behind `OS.has_feature("web")`.
- **Freed nodes:** `flash()`, `float_text()` and the battle banner tween either check `is_instance_valid` or are tweens bound
  to the node itself. No `_current as X` casts are left in `src/client`.
