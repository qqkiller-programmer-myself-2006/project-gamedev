# T38 — แปลเอกสารโปรเจกต์เป็นภาษาไทย

## Goal
เอกสารทั้งหมดในรีโปเป็นภาษาไทย (ตามที่เจ้าของงานสั่ง "ใช้ภาษาไทยทั้งหมด").

## Scope
`README.md`, `CONTEXT.md`, `docs/**/*.md` (adr, design, guides, plans, review, agents, README), `AGENTS.md`, `.ai/checkpoint.md` (เฉพาะส่วนที่เป็นอังกฤษ).
เอกสารที่เป็นไทยอยู่แล้ว (เช่น ADR-0007, AGENTS.md ส่วนใหญ่) ให้ข้าม หรือแก้เฉพาะประโยคอังกฤษที่หลงเหลือ.
ตรวจไฟล์ด้วยสคริปต์ (นับสัดส่วนอักษรไทย/ละติน) แล้วเรียงตามไฟล์ที่เป็นอังกฤษมากที่สุดก่อน; ไฟล์ใดใหญ่มาก (เช่น `docs/review/*` รายงาน QA) ให้แปลให้ครบ อย่าตัดทอนเนื้อหา.

## Rules
- ใช้ศัพท์ตาม `docs/design/thai-glossary.md` ทุกครั้ง; ศัพท์ที่ยังไม่มีในตารางให้เพิ่มแถวในตารางนั้น.
- **ห้ามแปล**: โค้ดใน code fence, คำสั่ง shell, path ไฟล์, ชื่อ identifier/ฟังก์ชัน/ตัวแปร/class, URL, ชื่อ label ของ GitHub, เลข issue/PR, ชื่อ branch, เลขเวอร์ชัน, ข้อความที่อ้างอิงข้อความในเกมแบบ verbatim (เช่น "Ready 2 of 3" ที่ตรงกับ UI) — ใส่ในเครื่องหมาย ` ` ไว้ตามเดิม.
- ชื่อหัวข้อ (heading) เปลี่ยนเป็นไทยได้ แต่ถ้ามีลิงก์ anchor ภายในเอกสารอ้างถึง ต้องแก้ anchor ให้ตรง ตรวจลิงก์สัมพัทธ์ทั้งหมดไม่ให้เสีย.
- ห้ามแก้ไฟล์ `.gd`, `.json`, `.po`, `.tscn` หรือโค้ดใด ๆ (มี executor อื่นกำลังแก้โค้ดอยู่).
- ชื่อไฟล์ไม่ต้องเปลี่ยน.

## Verify
- สคริปต์ตรวจ: ทุกไฟล์ `.md` ข้างบนต้องมีอักษรไทยเป็นส่วนใหญ่ของข้อความร้อยแก้ว (ไม่นับ code fence/inline code/URL).
- ตรวจว่าลิงก์ markdown สัมพัทธ์ทุกอันยังชี้ไฟล์ที่มีอยู่จริง.
- `git diff --stat` ต้องมีเฉพาะไฟล์ `.md`.

## Report
จำนวนไฟล์ที่แปล/ข้าม, ศัพท์ใหม่ที่เพิ่มใน glossary, ไฟล์ที่ยังเหลือเป็นอังกฤษและเหตุผล.
